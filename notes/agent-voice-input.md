# Agent 语音输入落地方案

> 目标：把无线麦克风从普通音频输入设备升级为 Agent 的硬件入口，让用户可以通过物理按键完成“开始说话、取消、发送、切换模式”等操作。
>
> 调研案例：WorkBuddy × HOLLYLAND 猛玛、Qoder × DJI Mic。资料核对日期：2026-09-18。

## 1. 结论

Agent 语音输入的关键不只是语音转文字，而是打通两条通道：

1. **音频通道**：麦克风向电脑持续提供清晰、低延迟的人声。
2. **控制通道**：麦克风实体按键直接控制 Agent 的录音、取消、发送和模式切换。

推荐采用“标准音频设备 + 标准化控制事件”的开放架构：基础功能兼容任意麦克风，合作硬件通过 USB HID、快捷键预设或厂商 SDK 提供免键鼠操作。这样既能快速上线，也不会被单一品牌和型号锁定。

## 2. 已落地案例

### 2.1 WorkBuddy × HOLLYLAND 猛玛 LARK A2

HOLLYLAND 官方合作页面展示了较完整的硬件直连交互：

- 单击麦克风按键：唤醒 WorkBuddy 语音输入。
- 长按：删除输入内容。
- 双击：发送指令。
- 支持在 Web 端配置 5 套热键模板，切换不同 Agent 或工作任务。
- 提供 AI 降噪、远距离无线拾音和约 7 小时续航。

这个案例的核心价值是：**把 Agent 的输入状态机映射到了麦克风实体按键**，用户离开键盘后仍然可以完成一轮指令交互。

参考：[HOLLYLAND 猛玛 × WorkBuddy 联名活动](https://www.hollyland.com.cn/workbuddy-collaboration-event/)

### 2.2 Qoder × DJI Mic

Qoder 的语音体系覆盖三种场景：

| 能力 | 场景 | 交互方式 |
| --- | --- | --- |
| 语音输入 | 口述一条 Agent 指令 | 转写到输入框，检查后发送 |
| 实时语音 | 连续讨论、边聊边推进任务 | 实时双向语音会话 |
| 录音纪要 | 保存会议或长时间交流 | 保存录音与转写结果 |

Qoder 设置中还提供：

- 支持的 DJI Mic 套件自动发送。
- 声纹识别，用于降低周围人声干扰。
- 语音润色，处理停顿、重复和标点。
- 常用词纠正，提高项目名、人名和技术术语的准确率。
- 输入设备选择和可配置快捷键。

这个案例的核心价值是：**软件侧形成完整的语音能力分层，并对特定硬件增加自动发送能力**。

参考：[Qoder Voice Input](https://docs.qoder.com/qoder/voice-input)、[Qoder Voice](https://docs.qoder.com/user-guide/quest/qoder-voice)

## 3. 两种路径对比

| 维度 | WorkBuddy × HOLLYLAND | Qoder × DJI Mic |
| --- | --- | --- |
| 主要场景 | 通用办公 Agent | 开发与编码 Agent |
| 硬件联动 | 实体按键覆盖唤醒、删除、发送 | 支持特定 DJI Mic 套件自动发送 |
| 软件形态 | Agent 语音入口 | 语音输入、实时语音、录音纪要 |
| 差异化重点 | 远距收音、免键鼠控制、热键模板 | 声纹、润色、术语纠正、上下文协作 |
| 可借鉴点 | 明确硬件按键协议 | 按使用场景拆分语音产品能力 |

二者共同验证了一个方向：麦克风不应只是系统输入设备，而应成为 Agent 的专用遥控器。

## 4. 推荐产品架构

```text
无线麦克风
├── 音频通道：USB Audio / Bluetooth / 2.4 GHz 接收器
└── 控制通道：USB HID / 全局快捷键 / 厂商 SDK
                ↓
桌面语音桥接程序
├── 设备识别与按键映射
├── 录音、VAD、降噪
├── 云端 ASR + 本地 ASR 后备
├── 术语纠正与文本润色
└── 权限、安全和状态提示
                ↓
Agent 输入层
├── 输入框填充
├── 预览与编辑
├── 确认或自动发送
└── 实时语音会话
```

### 4.1 音频通道

- 电脑端优先使用 USB Audio Class，免驱动、兼容性最好。
- 移动端可使用 USB-C 接收器；蓝牙模式需要逐应用验证麦克风输入兼容性。
- 桌面端录音建议统一转换为单声道 PCM，再交给 ASR。
- 短指令使用录音结束后转写；连续对话再使用实时流式转写。

### 4.2 控制通道

建议定义与品牌无关的控制事件：

```text
PTT_START       开始录音
PTT_STOP        停止录音并转写
CANCEL          取消本轮或清空输入
SEND            发送当前指令
TOGGLE_MODE     切换语音输入/实时语音/录音纪要
MUTE            暂停麦克风
```

推荐默认按键映射：

| 手势 | 默认动作 |
| --- | --- |
| 单击 | 开始/结束录音 |
| 双击 | 发送当前指令 |
| 长按 | 取消本轮或清空输入 |
| 三击 | 切换 Agent、工作空间或语音模式 |

所有动作都应允许用户重新配置，避免与麦克风原有的降噪、静音和录音按键冲突。

### 4.3 转写与文本处理

- 在线模式：采用云端文件转写或实时转写服务。
- 离线后备：使用 `whisper.cpp` 或 `faster-whisper`。
- 为每个工作空间维护术语表，例如项目名、包名、类名和常用英文缩写。
- 文本润色只处理重复、语气词和标点，不应擅自改变命令语义。
- 原始转写和润色结果可在调试模式下对照，但默认不长期保存音频。

参考：[OpenAI 实时转写](https://developers.openai.com/zh-Hans/api/docs/guides/realtime-transcription)、[whisper.cpp](https://github.com/ggml-org/whisper.cpp)、[faster-whisper](https://github.com/SYSTRAN/faster-whisper)

## 5. 产品分层

### 第一层：通用兼容

- 任意系统麦克风都能使用。
- 通过桌面端全局快捷键开始、取消和发送。
- 转写结果先进入输入框，由用户检查。

### 第二层：认证硬件

- 自动识别支持的麦克风型号。
- 读取 USB HID 按键事件。
- 提供开箱即用的实体按键映射和设备状态展示。
- 支持可选的免确认自动发送。

### 第三层：联名生态

- 固件预置 Agent 控制模板。
- 自动完成设备选择、增益和降噪配置。
- 支持声纹、专有降噪、设备电量及连接状态。
- 在包装、固件、桌面端和售后体系中提供联合支持。

## 6. 安全设计

- 默认采用“转写后预览”，自动发送必须由用户显式开启。
- 删除、推送、付款、发送消息等高风险操作仍走 Agent 原有确认流程。
- 录音时显示明确的视觉状态和系统托盘状态。
- 不采集密码、验证码、API Key 等敏感语音；产品界面需要持续提示。
- 临时音频在转写完成后删除；云端处理需说明上传范围和保留策略。
- 声纹识别只能降低误触发概率，不能替代身份认证和操作授权。

## 7. 实施路线

### 阶段一：软件 MVP

- 支持任意麦克风。
- 全局快捷键按住说话或单击开始/停止。
- 录音结束后转写并填入 Agent 输入框。
- 提供术语表、文本预览和手动发送。

### 阶段二：硬件适配

- 接入一个支持 HID 或可编程按键的麦克风。
- 实现开始、取消、发送三个核心事件。
- 增加设备识别、断连恢复、电量和固件版本展示。
- 建立不同操作系统和 Agent 客户端的兼容性矩阵。

### 阶段三：实时语音

- 增加流式转写、自动断句和声纹过滤。
- 支持连续语音讨论及 Agent 语音播报。
- 支持语音打断、审批卡片和后台任务状态播报。
- 开放硬件控制协议或合作伙伴 SDK。

## 8. 验收指标

| 指标 | MVP 目标 |
| --- | --- |
| 短指令端到端延迟 | 录音结束后 2 秒内出现文本 |
| 中文技术词准确率 | 配置术语表后达到 95% 以上 |
| 按键成功率 | 连续 1,000 次事件无丢失或重复 |
| 断连恢复 | 接收器重新连接后 5 秒内可用 |
| 安全性 | 默认不自动执行转写内容 |
| 离线能力 | 网络失败时可切换本地转写 |

## 9. 最小可行结论

最稳妥的落地顺序是：**先做兼容所有麦克风的软件语音入口，再做一款麦克风的按键深度适配，最后发展联名硬件和开放协议**。

WorkBuddy × HOLLYLAND 证明了实体按键可以覆盖完整的 Agent 输入流程；Qoder × DJI Mic 则证明了语音输入需要进一步分化为指令、实时对话和录音纪要。将两者结合，才能形成既开放又有硬件体验壁垒的 Agent 语音入口。
